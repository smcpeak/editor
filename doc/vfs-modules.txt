vfs-modules.txt
Explanation of the main VFS-related modules


See also vfs-module-dependencies.ded[.png].


VFS-related modules with no Qt dependence:

  rfa-msg

    Defines VFS_* (most of which end in "Request" or "Reply"), the
    serializable message structures for the protocol.  Also defines
    VFS_MT_*, the associated numeric message type codes.

  rfa-sync-local-client

    RFA_SyncLocalClient, which performs the VFS file system access locally
    as part of the VFS server process.

  nearby-file

    Defines IHFExists, a synchronous, non-cancelable, and Qt-free
    interface to a subset of VFS capability.  Implemented by
    RFA_SyncMultiClient for production use, and TestIHFExists for testing.

    TODO: It should expose cancelation and error messages.

VFS-related modules that use Qt core (QObject) but no GUI depedence:

  rfa-async-single-client

    RFA_AsyncSingleClient, the asynchronous VFS client.  Uses Qt slots
    and signals in its interface, and CommandRunner to manage its
    connection to the server process.

  rfa-async-multi-client

    RFA_AsyncMultiClient, which manages a set of RFA_AsyncSingleClient
    connections to VFS servers, one per host.  Also exposes
    RFA_AbstractAsyncMultiClient, an interface that can be mocked for
    testing.  The interface uses Qt slots and signals.

  rfa-sync-multi-client

    RFA_SyncMultiClient, which offers a synchronous but cancelable interface
    on top of RFA_AbstractAsyncMultiClient.  Waiting and cancelation are
    provided by SynchronousWaiter (hence there is a small GUI
    dependency).  This has Qt slots to interface with
    RFA_AbstractAsyncMultiClient, but does not use Qt in its public
    interface.

VFS-related that depends on Qt GUI:

  smqtutil/sync-wait

    SynchronousWaiter, an interface that allows a client to wait until
    a condition is true, but the wait can be canceled.  Depends on Qt
    QWidget but probably shouldn't.  Also provides a production
    implementation that pops up a GUI with a Cancel button, and a test
    implementation that does not.

Editor non-GUI modules that use VFS:

  editor-fs-server

    VFS server process, uses rfa-sync-local-client.

Editor GUI modules that use VFS:

  editor-global

    Uses rfa-sync-multi-client to read editor files.  Uses sync-wait too.

  editor-window

    Uses rfa-sync-multi-client to read and write editor files.  Uses
    sync-wait (with GUI dependence) for wait/cancel.

  editor-widget

    Uses rfa-sync-multi-client, sync-wait, and nearby-file for "open file at
    cursor".  Also uses rfa-async-single-client to update file status such as
    modified-on-disk.

  filename-input

    Uses rfa-sync-multi-client and sync-wait to create new directories.
    However, it primarily uses rfa-async-single-client to retrieve directory
    contents as the user navigates.

LSP modules that use VFS:

  lsp-get-code-lines

    Uses rfa-sync-multi-client, rfa-async-multi-client, and sync-wait to read file
    contents in order to show lines of code for the locations returned
    by an LSP query for "all uses", etc.

  lsp-client-manager

    Uses rfa-async-multi-client and sync-wait, passing them along to
    lsp-get-code-lines.
